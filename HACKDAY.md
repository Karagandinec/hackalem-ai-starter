## 1. Первые 20 минут на площадке — перенос каркаса

Только после официального старта. Git Bash, по одной команде:

```bash
cd C:/Projects/HackAlem
git fetch hack
git merge --allow-unrelated-histories hack/main -m "merge: стартовый коммит организаторов"
# merge упрётся в README.md — оставляем свой:
git checkout --ours README.md && git add README.md && git commit --no-edit
git push hack main:main
```

**Почему merge, а не force.** Репозиторий принадлежит организации: force-push может быть
закрыт защитой ветки, и это выяснится в самый неудобный момент. Merge сохраняет их коммит
и проходит при любых настройках.

**Что уезжает в командный репозиторий:** полная история каркаса с датами 10–11.09. Это
не нарушение, а исполнение п. 6.4: ранее созданный код обязан быть раскрыт. Раскрытие
лежит в README, исходник публичен, даты сходятся. Прятать историю — хуже, чем показать.

## 3. Ритм: прогресс каждый час (п. 6.6)

Отсутствие почасового прогресса — основание для дисквалификации всей команды (п. 12.2).
Коммитом это делать проще всего, но подходит любое доказательство: работающий кусок,
схема, тест, данные, макет.

- Коммит каждые 30–40 минут, обязательный — в конце каждого часа.
- Сообщения по-русски и по делу: что заработало, а не «fix».
- Перед каждым пушем: `git pull --rebase hack main` — иначе поймаем конфликт втроём.

## 4. Роли и параллельная работа

Правило одно: **каждый пишет в своих файлах.** Тогда rebase проходит молча.

| Кто | Что делает | Файлы, где он хозяин |
| --- | --- | --- |
| **Капитан (Виталий)** | разбор кейса, сценарий демо, предметка и данные, README под критерии, питч, коммиты и пуши | `README.md`, `backend/scripts/generate_demo_data.py`, финальный демо-сценарий |
| **Fullstack** | экраны и эндпоинты под кейс: что видно на дашборде, какие фильтры, какие поля | `frontend/src/pages/*`, `frontend/src/api.ts`, `backend/app/routers/core.py`, `models.py`, `schemas.py` |
| **AI / Prompt** | промпт агента, инструменты, JSON-схемы ответов, что модель пишет в базу, AI-метрики | `backend/app/ai/*`, `backend/app/routers/ai.py` |

Пересечения решаются словами, а не мержем:

- Поле в модели нужно всем — заводит **fullstack**, остальные ждут его коммит.
- `styles.css` и `Layout.tsx` трогает только fullstack.
- Тесты пишет тот, кто менял поведение, в свой файл в `backend/tests/`.

**Почему капитан не берёт код на себя.** На техотборе 45 баллов из 100 — это «проблема
и ценность» (15), «потенциал развития» (20) и «README и воспроизводимость» (10), то есть
текст и постановка, а не строчки. А на Demo Day 65 из 100 — ценность, масштаб и подача.
Капитан, ушедший в код, теряет команде больше, чем успевает написать.

**Разбивка пяти часов:**

| Время | Что происходит |
| --- | --- |
| 0:00–0:20 | разбор кейса, решение на словах, распределение задач |
| 0:20–0:40 | перенос каркаса, первый пуш, зелёная ссылка |
| 0:40–3:30 | параллельная работа, коммит каждый час |
| 3:30–4:15 | сборка демо-сценария целиком, проверка **на живой ссылке**, а не локально |
| 4:15–4:45 | README под критерии, финальные пуши в оба репозитория |
| 4:45–5:00 | заморозка, прогрев ссылки, репетиция показа |

## 5. Если команда не соберётся — соло-режим

Порядок, что резать первым при нехватке рук:

1. Не режем: рабочая ссылка, демо-сценарий «данные → модель → результат», README.
2. Режем первым: новые экраны. Хватит дашборда и одной таблицы под кейс.
3. Режем вторым: новые инструменты агента. Три существующих закрывают чтение, запись и агрегат.
4. Никогда не режем фолбэк AI и `make check` — падение демо на сцене дороже любой фичи.
