# HackAlem AI — каркас под трек «Добывающая промышленность»

Заготовка под хакатон **HackAlem AI** (Астана, МВЦ «EXPO»). Предметка выбрана заранее:
парк техники на разрезе и события с ней — отказы, простои, ТО, аварии. Конкретный кейс
внутри трека объявляют на площадке, поэтому модели широкие и рассчитаны на правку.

Здесь уже сделано то, что на любом хакатоне пишется первым и съедает первый час: запуск,
база, авторизация, дашборд, импорт данных, чат с агентом, логирование вызовов модели
и реалистичные демо-данные. Ставится за несколько минут.

**Даты** (с [hackalem.ai](https://hackalem.ai/)): 23.09 — офлайн-этап, старт 14:00;
24–28.09 — жюри и технические эксперты проверяют присланные проекты; 29.09 — Demo Day;
01.10 — награждение на Digital Bridge. Код смотрят не только на сцене, поэтому репозиторий
должен запускаться у постороннего человека с первого раза — это ровно то, что проверяет
`make check`.

## Что уже готово

**Backend (FastAPI + SQLAlchemy + SQLite)**

- health-check, CORS, конфиг из `.env`
- три модели под предметку: `Asset` (техника), `Event` (событие с ней), `User` (сотрудник)
- CRUD, фильтры по статусу, типу, участку и датам
- дашборд диспетчера: готовность парка, простои, отказы, выработка + график по дням
- демо-авторизация без JWT (логин, токен, `Authorization: Bearer`)
- **импорт CSV**: BOM от Excel, разделитель `;`, русские заголовки колонок — понимает сам
- **выгрузка CSV** по тем же фильтрам, что и таблица
- seed-скрипт и генератор демо-данных: 140 единиц техники, ~420 событий, износ влияет на отказы

**Модуль `backend/app/ai/`**

- обёртка над OpenAI: ретраи, таймауты, лимит токенов, кэш ответов
- Structured Outputs — ответ строго по JSON Schema
- function calling с тремя инструментами: чтение из БД, запись в БД, агрегат
- **агент в несколько раундов**: модель уточняет запрос по итогам ответа базы, а не бьёт вслепую
- **оценка риска отказа**: модель смотрит наработку и историю событий машины и пишет вывод
  обратно в базу (`ai_label`, `ai_score`)
- **заглушка-фолбэк**: нет ключа или упал API — приложение продолжает работать
- таблица `ai_calls`: промпт, ответ, токены, латентность, стоимость каждого вызова
- эндпоинт сводки `/api/ai/metrics`

**Frontend (Vite + React + TypeScript)**

- тёмная тема, сайдбар, роутинг
- диспетчерская: 4 карточки-метрики, график простоев, таблица техники
- парк техники: импорт CSV, оценка риска в один клик, выгрузка результата
- чат с агентом со стримингом ответа (SSE) и показом вызванных инструментов по раундам
- страница AI-метрик

## Быстрый старт

Нужны Python 3.11+ и Node 18+.

```bash
git clone https://github.com/Karagandinec/hackalem-ai-starter.git
cd hackalem-ai-starter
```

**1. Ключи**

```bash
cp .env.example .env      # Windows: copy .env.example .env
```

Открой `.env` и вставь `OPENAI_API_KEY`. Без ключа проект тоже запустится — AI будет
отвечать заглушкой, всё остальное работает.

**2. Зависимости и данные**

```bash
make setup
make seed
```

Нет `make` (обычное дело на Windows) — рядом лежит шим с теми же командами:

```powershell
.\make.cmd setup
.\make.cmd seed
```

**3. Запуск**

```bash
make dev          # или .\make.cmd dev
```

- фронт — http://localhost:5173
- API и Swagger — http://localhost:8000/docs
- демо-логин — `demo@hackalem.kz` / `demo`

**4. Проверка перед коммитом**

```bash
make check        # pytest + tsc --noEmit, обе команды завершаются сами
```

## Как подогнать под кейс

Трек известен, конкретный кейс — нет. Порядок действий, когда его объявят:

1. **Проверить модели.** `Asset` — главный объект (техника), `Event` — что с ним произошло.
   Если кейс окажется не про парк, а, скажем, про логистику руды или геологию — переименуй
   `Asset` в `Truck` / `Borehole` прямо в `backend/app/models.py`, поправь `schemas.py`
   и прогони `make seed`. Миграций нет намеренно.
2. **Перегенерить данные.** Марки техники, участки, типы событий и причины — в
   `backend/scripts/generate_demo_data.py`. Потом `make seed`.
3. **Поправить дашборд.** Четыре карточки и график считаются в одном месте — функция
   `dashboard()` в `backend/app/routers/core.py`. Там же `BREAKDOWN_TYPES` и `READY_STATUSES`.
   Метрику, где рост — это плохо, помечай `lower_is_better=True`, иначе фронт покрасит
   падение простоев красным.
4. **Настроить агента.** Промпт — `SYSTEM_PROMPT` в `backend/app/ai/agent.py`, число раундов
   инструментов — `MAX_TOOL_ROUNDS` там же. Нужен свой инструмент — добавь в
   `backend/app/ai/tools.py` (описание + функция + `TOOL_HANDLERS`).
5. **Подстроить разметку.** Что модель проставляет в `ai_label` / `ai_score` — задаётся
   инструкцией в `POST /api/ai/enrich` и схемой `ENRICH_SCHEMA`. Колонки файла для импорта —
   словарь `IMPORT_ALIASES` в `backend/app/routers/core.py`.
6. **Схема ответа модели.** Нужен строгий JSON — добавь схему в `backend/app/ai/schemas.py`
   и вызови `complete(..., json_schema=...)`.

## Полезные эндпоинты

| Метод | Путь                       | Что делает                                       |
| ----- | -------------------------- | ------------------------------------------------ |
| GET   | `/api/health`              | жив ли сервер, видит ли базу, есть ли ключ AI     |
| POST  | `/api/auth/login`          | демо-логин, возвращает токен                      |
| GET   | `/api/assets`              | техника с фильтрами по статусу, типу, датам       |
| POST  | `/api/assets/import`       | загрузка CSV (multipart, поле `file`)             |
| GET   | `/api/assets/export.csv`   | выгрузка отфильтрованного списка в CSV            |
| GET   | `/api/events`              | события: отказы, простои, ТО                      |
| GET   | `/api/dashboard?days=30`   | 4 карточки + ряд для графика простоев             |
| POST  | `/api/ai/chat`             | чат с агентом, поток SSE                          |
| POST  | `/api/ai/enrich`           | оценить риск отказа, результат — в базу           |
| POST  | `/api/ai/insights`         | Structured Outputs: выводы по состоянию парка     |
| POST  | `/api/ai/classify`         | Structured Outputs: разбор заявки или записи      |
| GET   | `/api/ai/metrics`          | сводка вызовов: токены, деньги, латентность       |
| GET   | `/api/ai/calls/{id}`       | полный промпт и ответ одного вызова               |

Полный список — в Swagger на http://localhost:8000/docs.

## Работа с Codex

В корне лежит [AGENTS.md](AGENTS.md) — Codex подхватывает его автоматически. Там стек,
команды, стиль и жёсткое правило: **`npm run dev` и `uvicorn` нельзя запускать как
команду проверки** — они не завершаются и вешают агента до таймаута. Проверка — `make check`.

Если правишь код руками, а не агентом, AGENTS.md всё равно полезен: это короткая памятка
по проекту.

## Если что-то не работает

| Симптом                                   | Что делать                                                      |
| ----------------------------------------- | --------------------------------------------------------------- |
| В сайдбаре «backend недоступен»           | Не поднят backend. `make dev`, проверь http://localhost:8000/docs |
| «⚠ AI в режиме заглушки»                  | Нет `OPENAI_API_KEY` в `.env`. Вставь ключ и перезапусти backend  |
| Дашборд пустой                            | Не залиты данные: `make seed`                                    |
| Поменял модель, а API отдаёт старое       | uvicorn без `--reload` держит старый код. `make dev` запускает с ним |
| `make: command not found`                 | Используй `.\make.cmd <команда>`                                 |
| 404 на модель / ошибка от OpenAI          | Поменяй `OPENAI_MODEL` в `.env` на доступную модель              |
| Кракозябры в консоли Windows              | Команды из Makefile уже ставят `PYTHONUTF8=1`; вручную — тоже    |
| Порт 8000 занят                           | `make dev BACKEND_PORT=8010` и поправь `VITE_API_URL` в `.env`   |
